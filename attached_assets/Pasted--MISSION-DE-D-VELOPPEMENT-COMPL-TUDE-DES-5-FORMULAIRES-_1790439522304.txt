# MISSION DE DÉVELOPPEMENT — COMPLÉTUDE DES 5 FORMULAIRES D'ACTIVITÉ CAPEF

Tu travailles directement sur le dépôt :

`ephson-productions/CAPEF---enrolement`

## OBJECTIF

Implémenter de manière **complète, production-ready et testée** les champs de production manquants dans les formulaires d'activité CAPEF pour :

1. Agriculteur
2. Pêcheur
3. Éleveur
4. Exploitant forestier
5. Artisan

Le travail concerne le flux complet :

```text
Formulaire étape 2
      ↓
État React
      ↓
handleAddLineItem
      ↓
Payload API
      ↓
Validation serveur
      ↓
PostgreSQL
      ↓
Synthèse étape 3
      ↓
MemberDetail
```

**Il ne suffit donc pas que les champs apparaissent visuellement.**

Ils doivent être correctement :

* saisis ;
* validés côté client ;
* envoyés dans le payload ;
* validés côté serveur ;
* persistés ;
* relus ;
* affichés dans la synthèse ;
* affichés dans MemberDetail.

# 9. VALIDATION CLIENT

Dans `handleAddLineItem`, valider les données **avant l'appel API**.

Pour chaque champ obligatoire :

* vide → invalide ;
* undefined/null → invalide ;
* NaN → invalide ;
* négatif → invalide ;
* 0 → valide.

Pour les products :

* au moins une ligne ;
* produit valide ;
* quantité valide ;
* unité valide ;
* FCFA valide ;
* `Autre` correctement renseigné.

En cas d'erreur :

1. ne pas appeler l'API ;
2. afficher une erreur inline sous le champ concerné ;
3. afficher le toast :

FR :

`Formulaire invalide`

EN :

`Invalid form`

4. donner le focus au premier champ invalide.

Ne pas remplacer cette validation par un simple toast.

# 10. VALIDATION SERVEUR — OBLIGATOIRE

Dans :

```text
artifacts/api-server/src/routes/members.ts
```

Créer une fonction :

```typescript
validateActivityLineItem(activityType, body)
```

Elle doit être exécutée :

```text
POST line-item
PUT line-item
```

### Ordre obligatoire

Pour POST :

```text
idempotence existante
        ↓
validation production
        ↓
normalisation / insertion
```

Pour PUT :

```text
idempotence existante
        ↓
fusion du body
        ↓
validation du payload fusionné
        ↓
update
```

Ne modifie pas le mécanisme d'idempotence existant.

## Règles communes

Toutes les catégories :

```text
superficieHa = finite number >= 0
productionFcfa = finite number >= 0
```

Agriculture / Pêche / Artisan :

```text
productionQuantity = finite number >= 0
productionUnit = string non vide
```

Élevage / Forêt :

```text
products = array
1 <= length <= 20
```

Chaque élément :

```text
name = string non vide, max 100 caractères
quantity = finite number >= 0
unit = string non vide
fcfa = finite number >= 0
```

En cas d'échec :

```http
400
```

avec :

```json
{
  "error": "Champs de production invalides",
  "fields": [
    {
      "field": "superficieHa",
      "code": "required"
    }
  ]
}
```

ou le message anglais correspondant si l'API utilise cette convention.

La validation doit se produire **avant INSERT/UPDATE**.
